Implementation Approach

"Dedicated Electron window" can mean different things. Pick the level of separation.

A

Secondary BrowserWindow

Separate Electron window with its own preload, IPC channel, and lifecycle. Launched from main process. Toggleable from the main app. Fully native OS window — can be minimized, snapped, etc.

Pros

  • True native feel
  • Can focus independently
  • Separate state

Cons

  • More IPC wiring
  • Two renderer processes
  • Memory overhead
B

Immersive App Route (Recommended)

Full-screen route in existing Electron renderer (/games). Removes all web chrome (header, sidebar). Custom title bar with native-looking controls. Same renderer = zero IPC duplication. Can use a CSS draggable region for window moves.

Pros

  • Fastest to build
  • No memory overhead
  • Shared state/query cache

Cons

  • Not truly separate window (yet)
C

Hybrid: Immersive Route + Toggleable Window

Build as immersive route first (B). Then add a "Pop Out" button that opens it as a secondary BrowserWindow (A) with shared state. Best of both — quick initial build, optional native pop-out later.

Pros

  • Fast initial build
  • Future native window
  • No regrets architecture

Cons

  • Slightly more code upfront
